# ADR-0009: 例外を使わない

- 状態: 承認
- 日付: 2026-10-07

## 背景
エラー処理の方式は、使えるライブラリ（JSON パーサなど）の選択にも影響するため、早い段階で決める必要があった。

## 決定
- 例外は使わない。エラーを 3 種類に分けて扱う。

| 種類 | 扱い方 |
|------|--------|
| 想定内の失敗（ファイルがない・値が不正） | `std::expected<T, Error>` で返す |
| 値がないことが正常（最も近い敵がいない） | `std::optional<T>` で返す |
| プログラムのバグ（不変条件の違反） | アサートで即停止 |

- ゲーム本体のターゲットは `-fno-exceptions` でビルドし、方針をコンパイラで強制する。テストのターゲットのみ例外を有効にする（Catch2 が内部で使うため）。
- 詳細は [error-handling.md](../error-handling.md)。

## 検討した選択肢
| 選択肢 | 長所 | 短所 |
|--------|------|------|
| **例外なし + expected / optional / アサート** | ゲーム業界の慣行（性能・コードサイズ・コンソール機の制約）。UE も既定で例外無効。失敗が関数の型に現れ、FP 方針と一致する | 例外を前提とするライブラリが使いにくい |
| 例外を使う | 標準ライブラリ・多くのライブラリの前提に沿う | 失敗が型に現れない。ゲーム業界・UE の慣行と異なる |

## 結果
- UE との対応: アサート ↔ `check()` / `checkf()`、`std::expected` ↔ `TValueOrError`。
- `-fno-exceptions` と MSVC 標準ライブラリの組み合わせでの動作は、立ち上げ時（arena M0）に確認する。
- JSON パーサの選択に影響した（[ADR-0010](0010-json-with-glaze.md)）。
