# ADR-0005: モノレポ構成（engine と games）

- 状態: 承認
- 日付: 2026-10-07

## 背景
- 当初（2026-10-06）は「1 題材 = 1 リポジトリ」とし、リポジトリ名を `cpp-<題材>`（例: `cpp-arena-survival`）、文書・設定ファイルは次のリポジトリへコピーして持ち出す方針だった。理由は、後から見返したときに関心が分離されているようにするため。
- ディレクトリ構成を検討する中で、共有モジュールとゲームを分けた構成なら 1 つのリポジトリに複数の題材を置けることが分かった。

## 決定
- **1 つのリポジトリで複数の題材を管理する（モノレポ）**。リポジトリ名は `cpp-game-lab`。
- 全題材で共有するモジュールは `engine/`、題材ごとのゲームは `games/<題材>/` に置く。
- 依存は `games → engine` の一方向のみ。`engine` から `games` への依存と、題材同士の依存は禁止。
- `engine/` は最初 `core` のみ。共有部品は、2 本目以降の題材で実際に必要になった時点で題材側から移す。
- 名前空間: 共有側は `engine::<module>`、題材側は `<題材の短縮名>::<module>`（例: `arena::sim`）。インクルードパスも同じ形（`<engine/core/...>`、`<arena/sim/...>`）。
- 詳細は [repository-structure.md](../repository-structure.md)。

## 検討した選択肢
| 選択肢 | 長所 | 短所 |
|--------|------|------|
| **モノレポ（engine + games）** | 共有部品をコピーせずに使える。共通化の過程（題材側 → engine への移動）が履歴に残る。UE の Engine とゲームプロジェクトの関係と一致する。ゲーム業界でも一般的 | 履歴に複数題材が混ざる → コミットのスコープとタグで分離する（[ADR-0013](0013-git-workflow-and-ci.md)）。共有部品の変更で古い題材が壊れうる → CI で常に全題材をビルド・テストする |
| 1 題材 = 1 リポジトリ（当初案） | 題材ごとに履歴が完全に分かれる | 共有部品・文書・設定をコピーで持ち回り、改善が各リポジトリに反映されない |
| ディレクトリを `apps/` 1 つにまとめる | 構造が単純 | 共有部品と題材固有のものの区別がディレクトリ名から分からない |
| 共通のルート名前空間（`lab::arena::sim`） | 名前の衝突により強い | 毎回長くなる。外部に配布しないため不要 |

## 結果
- 当初案の「`cpp-<題材>` のリポジトリ名」「文書・設定の持ち出し」は不要になった。
- 将来 UE 版を作る場合は `ue-game-lab` として並べられる。
