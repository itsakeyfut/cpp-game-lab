# ADR-0013: Git 運用と CI

- 状態: 承認
- 日付: 2026-10-07

## 背景
- 変遷を 1 歩ずつ追えるようにしたい。
- モノレポ（[ADR-0005](0005-monorepo-engine-and-games.md)）でも、題材ごと・共有部品ごとに関心を分けて履歴を見返したい。
- 共有部品の変更で古い題材が壊れていないことを保証したい。

## 決定
| 項目 | 方針 |
|------|------|
| ホスティング | GitHub |
| ブランチ | `main` + 短命な作業ブランチ。プルリクエストで `main` に取り込む |
| コミットメッセージ | Conventional Commits + スコープ（`feat(arena): ...`、`refactor(engine): ...`） |
| コミットの粒度 | 1 コミット = 1 つの意図。各コミットでビルドとテストが通る |
| タグ | 題材ごとのマイルストーンで `<題材>/vX.Y.Z`（例: `arena-survival/v0.1.0`） |
| CI | GitHub Actions で Windows（clang）+ Linux（clang）のビルド・テスト、整形チェック、clang-tidy。常に全題材をビルドする |

運用の詳細は [git-workflow.md](../git-workflow.md)。

## 結果
- スコープで題材ごとに履歴を絞り込める（`git log --grep="(arena)"`）。モノレポで関心を分離して見返すための主な手段になる。
- タグで「その時点の構成」を丸ごと取り出せる。
- Linux でもビルドすることで、特定 OS に依存した書き方を防ぐ。
