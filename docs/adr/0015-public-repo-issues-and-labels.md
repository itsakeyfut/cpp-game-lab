# ADR-0015: 公開範囲・Issue と PR の流れ・ラベルの体系

- 状態: 承認
- 日付: 2026-10-07

## 背景
- [ADR-0013](0013-git-workflow-and-ci.md) でホスティング（GitHub）、ブランチ、コミット、タグ、CI を決めたが、リポジトリの公開範囲、作業の単位（Issue）、マージの担当、Issue の分類方法は決めていなかった。
- GitHub にリポジトリを作成した時点で、これらを決める必要があった。
- 作業の単位と「なぜその作業をしたか」が Issue と PR に残れば、コミット履歴・ADR と並んで変遷を追う手がかりになる（[project-overview.md](../project-overview.md)）。

## 決定

### 公開範囲とライセンス
- リポジトリは **Public** で公開する。
- ライセンスは当面付けない（著作権者以外は利用できない状態）。付ける必要が出たら新しい ADR で決める。

### 作業の流れ
1. 作業ごとに Issue を起票する。まとまった目標（マイルストーンなど）は親 Issue を作り、作業を子 Issue（GitHub の sub-issues）に分ける。
2. Issue ごとに作業ブランチを作る。1 Issue = 1 作業ブランチ = 1 PR。
3. PR の説明に `Closes #<番号>` を書き、Issue と結びつける。
4. **マージはリポジトリの所有者が行う。** 作業者は PR を出したところで止まり、マージ後に次の Issue へ進む。

### ラベル
接頭辞で分類する。1 つの Issue に、各分類から 1 つずつ付ける（A- は複数可）。

| 接頭辞 | 分類 | ラベル |
|--------|------|--------|
| `S-` | 状態 | `Needs-Design` / `Ready-For-Implementation` / `Blocked` / `Experimenting` / `In-Progress` |
| `T-` | 種類 | `Bug` / `Feat` / `Doc` / `Experiment` / `Maintenance` / `Perf` / `Tracking-Issue` |
| `A-` | 領域 | `engine-core` / `arena-sim` / `arena-content` / `arena-app` / `build` / `ci` / `docs` |
| `D-` | 難しさ | `Trivial` / `Straightforward` / `Modest` / `Complex` / `Cpp-Semantics` |
| `P-` | 優先度 | `Critical` / `High` / `Medium` / `Low` |

- `A-` は CMake のモジュール単位で作る。題材やモジュールを追加したら `A-<題材の短縮名>-<module>` を追加する。
- GitHub の既定のラベル（`bug`、`enhancement` など）は役割が重なるため削除した。

## 検討した選択肢

### 公開範囲
| 選択肢 | 長所 | 短所 |
|--------|------|------|
| **Public** | 変遷そのものを学習記録として見せられる。GitHub Actions の標準ランナーを無料・無制限で使える（Windows ランナーの消費が多い CI と相性が良い） | コミットの作成者情報や誤ってコミットしたものが公開される → 秘密情報は扱わず、個人用の作業ファイルは `.gitignore` で除外する |
| Private | 作業途中の状態や個人情報が外に出ない | Actions の無料枠を消費する。学習記録として共有しにくい |

### マージの担当
| 選択肢 | 長所 | 短所 |
|--------|------|------|
| **所有者がマージする** | すべての変更が所有者の確認を経て `main` に入る。チーム開発でのレビュー承認後のマージと同じ形 | 作業ごとに確認待ちが発生する |
| 作業者がビルド・テスト成功後にマージする | 待ち時間がない | 確認されないまま `main` に入る |

### ラベル
| 選択肢 | 長所 | 短所 |
|--------|------|------|
| **接頭辞で分類した体系** | 分類ごとに 1 つ選ぶだけで付け方が揃う。絞り込み（`label:A-arena-sim`）がしやすい | ラベルの数が増える |
| GitHub の既定のラベル | 準備不要 | 状態・領域・優先度を表せない |

## 結果
- Issue・PR・コミット・ADR を `#<番号>` でたどれるようになる。
- ライセンスがないため、他者は閲覧のみ可能。公開範囲やライセンスを変える場合は新しい ADR で決める。
- 運用の詳細は [git-workflow.md](../git-workflow.md)。
