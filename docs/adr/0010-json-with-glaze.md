# ADR-0010: ゲームデータは JSON + glaze

- 状態: 承認
- 日付: 2026-10-07

## 背景
敵のパラメータ・ウェーブ構成・プレイヤーの性能などのゲームデータを外部ファイルから読み込む。例外を使わない方針（[ADR-0009](0009-no-exceptions.md)）と整合する必要がある。

## 決定
- 形式は JSON、ライブラリは glaze。
- 読み込みは次の流れを `std::expected` でつなぐ。
```
ファイル読み込み（副作用）→ JSON を DTO 構造体に変換 → 検証してゲーム用の型に変換（純粋関数）
     expected<string>         expected<EnemyDto>          expected<EnemyDef>
```

## 検討した選択肢
| 選択肢 | 長所 | 短所 |
|--------|------|------|
| **JSON + glaze** | 例外を使わずエラーを戻り値で返す。C++ の構造体と JSON を自動で対応づける（UE の `FJsonObjectConverter` が `USTRUCT` と JSON を変換するのと同じ考え方） | 新しい C++ 機能を多用するため、環境によって動作しない可能性がある |
| JSON + nlohmann/json | 最も普及している | 例外前提の設計。例外を切るとエラー時に強制終了になる |
| TOML（toml++） | コメントが書け、人が編集しやすい | ゲームデータの形式としては JSON ほど一般的でない |

形式に JSON を選んだ理由: UE の DataTable も JSON の読み込みに対応しており、ツールやエディタの支援が最も多い。

## 結果
- glaze の clang 20 + Visual Studio 2026 標準ライブラリでの動作は、使い始める時点（arena M5、可能なら M0）で確認する。問題があればこの ADR を廃止して選び直す。
