# ADR-0004: 題材シリーズと最初の題材

- 状態: 承認
- 日付: 2026-10-06

## 背景
1 本のゲームですべての学習テーマを扱うと関心が混ざる。題材ごとに主に学ぶテーマを分け、順に作っていきたい。最初の題材は、後続の題材が使う土台（立ち上げ・構成・共通部品）を作る役目も持つ。

## 決定
- 題材シリーズを次の順で作る（予定。各題材の開始時に見直す）。

| # | 題材 | 主な学習テーマ |
|---|------|---------------|
| 1 | アリーナ・サバイバル（3D 見下ろし型ツインスティック・シューター） | 土台一式: 立ち上げ、ゲームループと固定タイムステップ、合成、イベント、Result / Option、設定ファイル |
| 2 | 3D グリッドパズル（倉庫番風） | 不変データと状態遷移、Undo / Redo、リプレイ、決定論的テスト |
| 3 | タワーディフェンス | データ駆動設計、純粋関数としての経路探索、ステートマシン、UI と経済 |
| 4 | 物理アクション（プラットフォーマー） | 数値積分、衝突検出と解決、キャラクター制御 |
| 5 | ターン制タクティクス（SRPG） | アビリティ / エフェクトのデータ設計（UE の Gameplay Ability System に対応） |
| 6 | コロニー / RTS ライト | 大量エンティティ、ECS、並列処理、AI |

- 最初の題材はアリーナ・サバイバル。

## 検討した選択肢（最初の題材）
| 選択肢 | 長所 | 短所 |
|--------|------|------|
| **アリーナ・サバイバル** | リアルタイム更新・イベント・合成・設定ファイルが一通り登場し、土台作りに向く | — |
| 3D グリッドパズル | 純粋関数・Undo の学習に最適 | ターン制のため、ゲームループ・Tick の土台が作れない |
| タワーディフェンス | データ駆動の学習に良い | 経路探索・UI が増え、初期規模が大きい |
| 物理アクション | — | 物理・衝突解決に学習の焦点が逸れる |

## 結果
- 当初は「1 題材 = 1 リポジトリ」とし、文書や設定ファイルを次のリポジトリへ持ち出す想定だった。この方針は [ADR-0005](0005-monorepo-engine-and-games.md) で変更し、1 つのリポジトリ内に題材を積み上げる形になった。
- 題材の一覧と状態は [project-overview.md](../project-overview.md) で管理する。
